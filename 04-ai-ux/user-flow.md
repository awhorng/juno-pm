## Entry point

**Signal type:** New message / transcript received

A new transcript is ready for review

**What they see instantly**

Juno is reviewing the transcript

## The flow

1. Juno first checks the Strategy Document section to ensure it aligns with the latest rules. Then it signals how many requests it has found. Finally, it will say how many actions it can complete. 
2. Checking request against Strategy -> Identified # of requests -> Complete # of requests -> Generating report
3. If the P0 request aligns with the strategy doc, Juno will log the ticket as a valid request. Otherwise, Juno will flag certain requests as out of scope and ask the Product Manager to review. 

## AI moments

**Placement:** Full-Page Canvas

P0 tickets identified. Please validate that non-P0 tickets are correctly tagged. 

Sometimes non-P0 tickets depend on other tickets being resolved prior. This ensures you don't miss any tickets that may need to be resolved alongside a P0 ticket. 

## Fallbacks

**Kill switch**

Manual Priority change -> allows the PM to change the status as needed.

**Training signal**

Change request needs to be logged - justification needs to be provided. 

**Fail-safe**

If prioritization is not available, return the error message "Unable to determine Priority. Please review Strategy Doc or settings"
